# CBOS Pilot Sales Process

## Objective

Find practices with a real follow-up problem, test fit honestly, and offer a small paid pilot without presenting CBOS as an EHR replacement.

## Stages

| Stage | Required evidence | Exit decision |
| --- | --- | --- |
| Target | Practice matches the ICP hypothesis | Contact / deprioritize |
| Discovery | Current workflow, owner, pain, data path, and decision maker understood | Demo / stop |
| Task-based demo | Practice completes the validation tasks with fake data | Pilot offer / revise / stop |
| Paid pilot offer | Scope, price, data gate, and success criteria understood | Accept / decline |
| Onboarding | Owner, data mode, baseline, training, and reviews confirmed | Start / pause |
| Day-30 review | Scorecard and qualitative evidence completed | Continue / revise / stop |

## Qualification rules

Proceed when the practice has a visible follow-up gap, can name a workflow owner, has an acceptable data path, and agrees CBOS is not replacing clinical or billing software.

Stop when the buyer primarily wants an EHR/scheduler, the existing system already solves the workflow, no one will own daily use, or value depends on unsafe data handling or duplicate entry.

## Claims discipline

Say:

- improve visibility;
- make follow-up work easier to see;
- test whether a consistent queue reduces missed opportunities;
- measure use and workflow fit during the pilot.

Do not say:

- guaranteed revenue or recovered patients;
- HIPAA compliant without formal determination;
- automatic EHR integration before validation;
- proven time savings without measured pilot evidence.

## Required records

After each meaningful interaction, record source, role, actual words, objections, decision, next action, owner, and evidence still missing. Do not convert interest into a stronger claim than the person made.
